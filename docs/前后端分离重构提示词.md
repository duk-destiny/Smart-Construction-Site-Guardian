## 一、项目背景

本项目「智护工地」是施工安全 AI 监控系统（动火作业 + 施工 PPE 双场景），位于仓库 `hzz-fire-safety/`：

- 技术栈：Python 3.13 / Streamlit 1.60 / SQLite / ONNXRuntime CPU 推理 / BGE + ChromaDB RAG / 可选 Ollama LLM
- 分层声明：ui → services → agents → core → dao（见 app.py 模块注释与 docs/代码规范.md）
- 当前形态：Streamlit 单体；实时监测每个浏览器会话各跑一套推理循环（O(观看人数) 成本）
- 开发模式：一人全栈，代码全部由 AI 辅助生成，维护者不深入前端

重构目标：
1. 修复 ui→services 分层破坏（约 15 处直连）
2. 后端包 FastAPI 接口层，为移动端/第三方集成铺路
3. 前端迁移到 React SPA（React 18 + TS + Vite + AntD 5）
4. 实时监测改为「后端单推理循环 + WebSocket 帧广播」，推理成本降为 O(1)
5. 过程中顺带修复已探明的安全漏洞与质量问题（清单见 Phase 1）

## 二、硬性约束（任何 Phase 不得违反）

1. **离线部署**：全链路零外网依赖。前端构建产物本地打包（Vite build → FastAPI StaticFiles 挂载），禁止任何 CDN 引用
2. **纯 CPU**：禁止引入 GPU 依赖；保持现有 CUDA_VISIBLE_DEVICES="" / OMP_NUM_THREADS=1 抑制配置（torch+onnxruntime 同进程会原生段错误，BGE 已隔离到 core/bge_worker 子进程——勿动这套架构）
3. **轻链路原则**：实时监测路径纯规则，不调 RAG/LLM，告警当帧出
4. **目录策略**：Python 代码留在仓库根目录（agents/ core/ dao/ services/ ui/ scripts/ tests/ 不迁移），新增 `api/` 包与 `frontend/` 目录
5. **回归底线**：每个 Phase 结束 pytest 全绿（scripts/run_tests.py）；Phase 3 完成前 Streamlit 旧版必须始终可启动
6. **数据库**：变更只能走 dao/db.py 的 _MIGRATIONS 追加式迁移，禁止破坏性重建
7. **部署形态**：单进程单机；不引入消息队列/Redis/多副本

## 五、Phase 2 — FastAPI 接口层

新增 `api/` 包（FastAPI），只允许 import services 层，与 ui/ 平级：

- **api/main.py**：应用工厂；frontend/dist 存在才挂载静态；全局异常处理；/healthz 端点
- **api/deps.py**：JWT 认证依赖（HS256，过期 12h，secret 来自配置/环境变量）；角色依赖（admin/safety/responsible）
- **api/routers/** 按资源拆分：
  - auth：login / change-password / me
  - tasks：POST 上报（multipart，图片/视频 + 作业票字段）、GET 任务列表/详情/进度（轮询，预留 SSE）
  - alarms：GET 列表/详情、POST 误报标记 / 转工单
  - orders：GET 我的工单 / 全部(admin)、POST 整改提交（照片 multipart）、POST 验收/驳回、GET 逾期列表
  - reports：GET 周报列表 / 周报 PDF 下载
  - admin：模型列表/切换、用户管理、知识库、webhook 测试、系统自检（全部 admin-only）
  - ws：/ws/realtime（Phase 4 用）
- 复用现有 TaskService/DispatchService/ReportService/AuthService，**禁止在 router 里写业务逻辑或 SQL**
- 异步上报沿用现有后台研判 + 进度轮询机制；TaskService._progress 类级 dict 的读取暴露成 API（单进程内可接受）
- CORS 仅开发模式放行 localhost:5173（Vite dev server）
- docker-compose 更新：api 服务 + 健康检查；文档标注容器内 Ollama 需 host.docker.internal（现有 localhost 配置在容器内不可达）

测试：pytest + httpx AsyncClient，覆盖每个端点正常路径 + 权限拒绝路径（safety 访问 admin 端点必须 403）；上传端点用恶意文件名/超限文件做负向用例。

验收：httpx 全端点走查通过；Swagger 文档可用；pytest 全绿；Streamlit 未动。

## 六、Phase 3 — React 前端

`frontend/` 目录：React 18 + TypeScript + Vite + Ant Design 5。

- 基线：react-router-dom v6 按角色路由守卫；axios 封装（拦截器统一处理 401/403/错误提示）；图表用 @ant-design/charts 或 echarts（按需引入）；不引入 Redux 等重型状态库
- 页面映射（功能对齐现有 Streamlit，视觉可优化）：
  - 登录页（含强制改密流程）
  - 统一上报：影像研判（上传 + 进度轮询 + 结果面板）/ 文字线索建单 / 对话式查询（接现有 intent_router，只读）
  - 多 Agent 研判：分步展示各 agent 输出（数据源为任务详情的 agent_runs）
  - 工单：列表/详情/改判/导出 Excel
  - 历史分析：日期筛选 + 统计图表
  - 实时监测：Phase 4 完成前先做告警只读列表占位
  - 我的整改单（responsible）：工单列表 + 拍照/传图提交 + 验收状态——**按手机浏览器可用设计（响应式）**
  - 管理端（admin）：用户/模型/知识库/webhook/自检
- 构建：`npm run build` → frontend/dist 由 FastAPI 挂载，单进程单端口部署
- UI 层零业务逻辑零 SQL，一切经 api/routers

测试：Vitest 组件冒烟；关键流程 Playwright 冒烟（登录→上报→查结果→提交整改）。

验收：浏览器全流程走查（登录/上传研判/建单/整改/验收/周报下载）；断网环境完整可用；Streamlit 保留可运行作为回退；README 标注两套入口。

## 七、Phase 4 — 实时链路重做（收益最大）

- **后端唯一推理循环**：新增 api/realtime_hub.py 常驻线程汇聚多路帧源，检测→规则合规→告警（沿用 core/realtime_engine + services/monitor_service 并收敛）
- **WebSocket 广播**：/ws/realtime 推 JPEG 帧 + 叠加框 + 告警事件 JSON；N 个观看者共享一路推理；无人观看时降频保活（如 1fps）或暂停推理（可配）
- **per-source tracker**：core/realtime_engine.py:44 共享 IoUTracker 改为按源字典，消除跨摄像头 ID 串扰，解锁并行 analyze
- **reload 加锁**：core/realtime_engine.py:77-85 改 build-then-swap（新列表构建完后原子替换 self.engines），消除与检测线程竞争
- **TaskService 类级可变状态**（task_service.py:24, 68-69）加锁或落 DB，消除 TOCTOU 重复运行
- **前端实时页**：canvas 渲染 WebSocket 帧 + 告警弹窗 + 声音（沿用现有 base64 音频方案）

验收：两个浏览器同看一路摄像头，后端日志确认只有一路推理；admin 页触发引擎切换过程中检测不崩；告警当帧弹出；pytest 全绿。

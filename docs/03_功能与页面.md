## 页面与角色（React 前端）

路由守卫按角色注入菜单（`frontend/src/router.tsx`），`must_change_password=true` 强制跳改密页：

> 本页描述 **AI 助手 + 影像研判双窗口**及各业务页：同一套 services 层之上，多模态智能体的「眼睛」（影像研判/实时监测）、「大脑」（AI 助手）与「手脚」（工单闭环）分窗口协作。

| 路由 | 页面 | 角色 | 功能 |
| --- | --- | --- | --- |
| `/login` | 登录 | 所有人 | 账号密码登录，JWT 12h |
| `/change-password` | 修改密码 | 已登录 | 原密码 + 新密码（≥8 位），首登强制改密门控 |
| `/chat` | AI 助手 | admin / safety | 对话大窗：会话管理（新建/改名/归档/删除/批量操作）、消息气泡（快路径卡片+认知确认卡，刷新自动恢复未完结任务）、影像附件分析、语音输入/朗读（按部署能力检测，未配置弹窗提示"模型暂未拥有该能力"）、上下文管理（最近轮原文注入规划）与跨会话记忆（其他会话要点）、问候/寒暄规则快路径零 LLM 直答、工具抽屉（文字建单/视频分析/周报生成/快捷查询）；顶栏支持暗色/亮色与四套主色切换（本地偏好） |

## 核心特性总览

- **双模式**：上传研判走五段流水线重链路（深度推理、可读工单），实时监测走轻链路（低延迟、连续预警）；
- **多场景检测**：动火作业（火花/烟雾/灭火器）+ 施工 PPE（安全帽/反光衣/人员），检测头按场景配置可扩展；
- **三级合规**：红（不合规/即时高危）/ 黄（警告）/ 绿（合规），分级规则数据驱动，可不改代码调整；
- **工单闭环**：派发到人（responsible 角色 + config 规则映射，时限按风险等级查表）→ 整改提交（说明+现场照片）→ 验收销项/驳回重改 → 逾期巡检催办越级，五类动作全落审计；
- **风险周报**：检测×告警×工单三源确定性聚合（含按责任人派发/销项/在办/逾期率画像），规则化结论 + fpdf2 中文 PDF；
- **AI 助手窗口**：文字建单（工具卡片，severity 白名单下拉+查表定级跳过视觉链路直达派发闭环）、「3号工单怎么样了」「近7天逾期」「本周统计」一句话出结果（双层路由：规则快路径毫秒级直返；周报撰写/根因/证据问答/视频分析转认知层异步规划）、影像附件随对话上传（服务端校验并强制绑定给分析工具）；
- **AI 提取预填**：双 Provider 云 key 失败自动落本地 Ollama，越白名单即弃，仅草稿人工确认；
- **语音转写（可选）**：`asr.*` 未配置时入口完全静默，离线能力零依赖；
- **上传链路异步化**：后台研判 + 进度轮询，点击即响应；
- **告警生命周期 + 外部推送**：高危帧自动创建告警事件、证据截图留存、异步推送到企业微信/钉钉/通用 Webhook，按 `(source, cls)` 冷却去重；
- **模型版本管理**：版本注册、新旧指标对比、一键切换（管理端 UI）；
- **工程化**：服务层权限校验、审计日志、统一测试/启动脚本、Docker 容器化、GitHub Actions CI、SonarCloud 质量门禁；
- **内建自检与演示模式**：系统自检页一键跑全链路清单（模型/源/webhook/DB/假告警→推送）；notify 演示模式免 webhook 回环捕获；视频源支持 `demo://` 合成帧，无 key/无摄像头即可自检。

## 检测能力（当前双场景）

| 场景 | 检测类别 | 模型 | 推荐阈值 |
| --- | --- | --- | --- |
| `hot_work` 动火作业 | 火花 / 烟雾 / 灭火器 | YOLOv8s ONNX `yolov8_fire_smoke_v*.onnx` | 0.35（烟雾 F1=0.91、火花 F1=0.78） |
| `construction_ppe` 施工 PPE | 安全帽 / 未戴帽 / 反光衣 / 未穿衣 / 人员 | YOLOv8 ONNX `ppe_yolov8_v*.onnx` | 0.25（no_helmet F1=0.73、no_vest F1=0.73） |

场景配置见 `config/config.yaml` 的 `scenes.*`，检测白名单与中文释义见 `core/yolo_engine.py` 的 `WHITELIST` / `WHITELIST_CN`。

## 三级合规

| 级别 | 颜色 | 含义 |
| --- | --- | --- |
| 不合规 | 红 | 即时高危（火花/烟雾/未戴安全帽等），红框高亮 + 声音警报 |
| 警告 | 黄 | 需关注（易燃物/未穿反光衣等） |
| 合规 | 绿 | 无违规目标或仅检出安全信号（已佩戴安全帽/反光衣/人员在场） |

分级规则数据驱动，见 `config/config.yaml` 的 `compliance.severity`，键为项目隐患键，值为 `safe/warning/critical`，可在不改代码的前提下调整。

## 影像研判流水线 · 五段职责

| 段（Stage） | 角色 | 职责 | 是否调模型 |
| --- | --- | --- | --- |
| 视觉检测 VisionStage | 巡检员 | YOLO 逐帧/逐图检测，映射违规中文描述 | ✅ YOLO ONNX |
| 规范检索 RuleStage | 资料员 | 作业票字段检查 + RAG 规范条款检索与匹配 | ✅ BGE Embedding + Chroma（第二趟；embedding 检索，非 LLM） |
| 融合定级 FusionStage | 安全主管 | 风险矩阵查表定级 + 误报过滤（火花低置信/矛盾框） | ❌ 纯规则 |
| 复核 ReviewStage | 质检员 | 高风险低置信项/条款未命中 → 标记人工复核 | ❌ 纯规则判定 |
| 处置 ActionStage | 督办员 | 组装整改工单 + 工人白话提示（模板为主，LLM 可选润色） | ⚠️ LLM 可选，降级为模板 |

> 命名说明：五段是 `pipeline/` 包中的**确定性流水线组件**（原 `agents/` 包 `*Agent`，v2.1 起降级为认知层 `run_video_pipeline` 工具的内部实现并更名 `*Stage`），不是 LLM 智能体；系统的顶层智能体是 Agent 认知层（见 02 架构）。

编排器 `pipeline/orchestrator.py`：DAG 为 `[视觉 ∥ 规范] → 融合 → 复核 → 处置`，顶层 try/except 兜底，任一段崩溃标红不退出进程，整体状态取 `failed > degraded > success`。

复核段判定 `needs_review` 时后台异步调 LLM 产出「辅助理解」意见（可能原因/现场复核要点/建议优先级，≤200 字），落 agent_runs 证据链并在研判页以紫色意见卡展示（明确标注「仅辅助理解·不改变定级」）。

## 工单闭环

```
建单（影像研判/文字上报/告警转工单）
  → 派发到人（dispatch.rules 规则映射 or 手动选择，时限：重大1h/较大2h/一般24h/低168h）
  → 整改提交（说明 + 现场照片 ≤4 张）
  → 验收销项 / 驳回重改（驳回原因展示给责任人）
  → 逾期巡检催办越级（演示用管理端按钮+时间游标，生产由 cron 驱动 scripts/overdue_scan.py）
```

- 催办 webhook 化：复用告警通道，双档推送责任人/越级管理层；
- 单张工单可导出台账 Excel；
- 五类动作（dispatch/submit/approve/reject/urge）全落 `audit_logs`。

## 人工纠偏闭环

- 安全员改判或逐目标纠偏后自动写入 `feedback_samples`（`pending`）；
- 管理端可审核 `pending / confirmed / rejected`；「导出纠偏样本 CSV」含 `status` 列，不筛即完整审计流水，筛 `confirmed` 即已审核训练子集；
- `scripts/build_feedback_dataset.py` 将**仅 `confirmed`** 的样本转为场景级 YOLO 数据（`data/feedback_training/yolo/`），防止未审核纠偏污染模型；
- `scripts/prepare_combined_dataset.py` 合并训练集时 `fb_` 前缀纠偏样本并入 `data/combined/<scene>/train/`，闭环「识别 → 纠偏 → 审核 → 回写训练集 → 复训」端到端打通；
- 闭环幂等与防污染：合并按目标文件名判重（`{scene}_{task_id}_{id}` 唯一，重复跑只记 `already_exists`）；纠偏数据只写生成目录 `data/combined/`，永不回写 `data/raw/`；`pending/rejected` 在生成步即被过滤；
- `ui/correction_workbench.py` 提供可视化逐目标纠偏工作台（原图 + 检测框 + 修正框）。

## 告警与外部推送

- 高危帧自动创建告警事件 → 现场标注帧截图留存（`data/alarms/`）→ 异步推送到企业微信/钉钉/通用 Webhook；
- 推送结果写 `notification_logs` 留痕（sent / failed / skipped），管理端可测试推送并追溯；
- 支持多路 RTSP 后台自动轮询（`monitor.*` 配置），按 `(source, cls)` 冷却去重，持续违规可周期性告警；
- 默认关闭，配置见 `config/config.yaml` 的 `notify.*` / `monitor.*`；演示模式 `notify.demo_mode: true` 免 webhook 回环捕获 payload。

## 模型版本管理

- 管理端复训任务支持启动/轮询/早停/导出 best.pt 为 ONNX，训练完成自动注册到 `model_registry`（`active=False`，不动当前线）；
- 新旧指标对比展示，可一键切换为当前版本（回写 `config.yaml` + 运行中引擎热加载）；
- `scripts/register_model.py` / `scripts/switch_model.py` 为命令行注册/切换入口；
- `scripts/evaluate_models.py` 在测试集上计算各隐患类别 Precision/Recall/F1，写入 `data/eval/model_eval.json`（口径见 [06 测试与评测](06_测试与评测.md)）。
